# NutriAI Dietitian Web Panel -- Complete Frontend Architecture Plan

## Technology Decisions

Based on the specs:
- **React 18** with TypeScript
- **Vite** as build tool
- **TailwindCSS 3** for styling
- **shadcn/ui** for component library (Radix-based)
- **Recharts** for all charts/graphs
- **Zustand** for state management (lightweight, spec mentions Zustand or Context)
- **React Router v6** for routing
- **Socket.io-client** for real-time communication
- **Axios** for HTTP requests
- **react-hook-form + zod** for form validation
- **date-fns** for date utilities
- **jsPDF + html2canvas** for PDF export
- **Jitsi Meet** (iframe embed) for video calls
- **Lucide React** for icons (shadcn/ui standard)

## Key Architectural Decisions

1. **shadcn/ui over full component library**: The components are copied into `src/components/ui/` and fully customizable. This matches the spec's recommendation.

2. **Zustand over Redux/Context**: Lightweight, minimal boilerplate, TypeScript-first. Five small stores instead of one monolithic store.

3. **Service layer with mock data**: Every `src/services/*.service.ts` file imports from `src/mock/` during development. When the backend is ready, swap mock imports for actual axios calls. The service interface does not change.

4. **Socket.io as a singleton**: `src/lib/socket.ts` creates one connection, `useSocket` hook provides typed event subscription, `socket-store` tracks connection state.

5. **Tab-based patient detail**: Instead of 7 separate pages per patient, one page with 7 tabs. This reduces routing complexity and allows the header/quick-stats to persist.

6. **Charts with Recharts**: All chart components in `src/components/charts/` are standalone, receiving data as props. They are reusable across dashboard, patient detail, and reports pages.

7. **Admin routes are nested**: Admin pages share an `AdminLayout` with a different sidebar, nested under `/admin/*`. Guarded by `AdminRoute` component checking role.
